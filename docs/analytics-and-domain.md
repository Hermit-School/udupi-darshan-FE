# Analytics and domain setup

## Google Analytics

The existing Firebase project is `udupi-darshan`, with measurement ID `G-H9V2CJGX4K`. This release retains that property and explicitly sends page views on successful public Angular route changes. Query strings, story form contents and admin pages are excluded from these explicit events. Analytics failure does not block the website. The initial automatic page view is disabled so that the Angular navigation supplies it.

Account steps for the property owner:

1. Open the Firebase project and its linked Google Analytics property. Verify that `G-H9V2CJGX4K` is the intended web data stream.
2. In the web stream's Enhanced Measurement settings, disable automatic **Page changes based on browser history events**. The application sends page views explicitly; leaving history tracking enabled can produce duplicate events. Check any separate Google Tag Manager tags for the same reason.
3. In Analytics property access management, grant the intended owner/reviewer account (`udupidarshan09@gmail.com`, if confirmed) the appropriate role. An email address in application code cannot grant Analytics access.
4. After deployment, use Realtime/DebugView to verify one page view per public route navigation, including direct hash URLs, back/forward, and Events. Confirm that admin routes do not produce manual page views. Use engagement/retention reports for returning visitors; the footer counter is a separate visit count, not an Analytics user count.

Reference: https://developers.google.com/analytics/devguides/collection/ga4/single-page-applications

The existing property/account access and dashboard delivery have not been independently verified from the code workspace. These account-side checks remain open.

## udupidarshan.com

The owner confirmed that the domain still needs to be purchased. No domain purchase or DNS change is included in the code push.

1. Purchase the domain through the owner's chosen registrar using the owner's account, billing details, and renewal preferences. Verify availability and the total renewal cost at purchase time.
2. In Firebase Hosting for `udupi-darshan`, choose **Add custom domain**. Add `udupidarshan.com`; configure `www.udupidarshan.com` as an additional domain or redirect.
3. Copy the exact ownership-verification TXT and Hosting DNS records generated by Firebase into the registrar's DNS panel. Do not substitute guessed record values or remove unrelated mail records.
4. Wait for Firebase to verify DNS and provision HTTPS. Test the apex and www URLs, direct hash links, image/photo URLs, login, story submission, and browser back/forward before advertising the new address.
5. Add `https://udupidarshan.com` and `https://www.udupidarshan.com` to the backend's `CORS_ALLOWED_ORIGINS`, retaining the existing Firebase origins during the transition. Add the domain to the Analytics web stream as appropriate.

The frontend recognizes both custom hostnames when resolving internal article links. The existing Firebase address remains usable during domain setup.
